# 技能侦探 · Skill Detective

本插件由 CyberMind-labs 的 52yin14n9、Admie、Assomeity、George 联合开发。

DeepSeek Harness（DSH）的技能管理 bundle：发现未覆盖的任务需求，检索候选，审查完整技能目录，并管理安装、启停、作用域和审查记录。模型审查、文档检查与会话执行限制分别展示，不能互相替代。

## 安装与更新

使用 Git 主干代码，可克隆仓库并将本地目录加入实际使用的 DSH profile：

```sh
git clone https://github.com/CyberMind-labs/dsh-skill-detective.git
dsh plugin --profile desktop add "/absolute/path/to/dsh-skill-detective"
```

将路径替换为仓库的绝对路径（Windows 例如 `D:/Projects/dsh-skill-detective`），并将 `desktop` 替换为实际 profile 名，再在插件管理页面启用 bundle；也可直接在管理器中安装本地目录。更新本地源码后，重载或重启 Host，再刷新 Web 页面：

```sh
cd dsh-skill-detective
git pull --ff-only
git rev-parse HEAD
```

插件管理器也可按包名 `dsh-skill-detective` 安装 npm 版本。**Git main、Git tag/Release 与 npm dist-tag 是独立渠道**，更新 Git 不等于发布 npm。当前 `package.json` 保持 `1.5.0`，本次改动按 Git 提交识别，不能仅凭相同版本号判断是否包含修复。全局 `npm install -g` 不会自动接入 DSH profile。

## 开始使用

两个开关都按会话生效，作用不同：

| 控件 | 作用 |
| --- | --- |
| 输入框「🐟 技能侦探」 | 默认关闭；控制后续消息的需求判断与推荐，不授予工具执行权限 |
| 技能管理页「会话工具保护」 | 对明确选中的会话强制限制工具调用；默认模式为只读，开启推荐不会自动开启保护 |

1. 在已配置可用模型的会话中启用「技能侦探」。若技能管理页的会话列表为空，先发送一条消息再返回。
2. 打开「技能管理」，明确选择「用于审查的会话」。安装、整合和复审使用该会话的模型，不猜测最近会话。
3. 为准备使用技能的会话开启「会话工具保护」。默认只允许工作区文件读取；需要写文件时，由用户明确选择「工作区内文件读写」再应用。
4. 在市场搜索并安装，或回到该会话发送任务，在推荐气泡中点击「帮我找」。知识问答、已覆盖任务或判断失败时可能不推荐；「先不用」记录忽略规则，可在设置中恢复。
5. 详情中检查来源、目录、作用域和审查证据。临时作用域必须绑定有效会话；缺少运行保护时，安装或启用会提示先开启受限执行。

管理页支持扫描、分组、搜索、实例详情、启停、删除、作用域迁移及冲突确认。同名技能通过 `instanceId` 和路径区分；覆盖、改名或取消需明确选择。插件自带技能仅可查看。

## 审查证据与文档检查

远程安装固定 Git 提交，获取完整目录清单并核验下载内容。安装会对**最终 staging 目录**再次做完整快照与审查，核对待发布目录后再切换；不把只审查 `SKILL.md` 当作整个技能已审查。读取失败、链接、特殊文件、未知/不可审查格式或超限目录会拒绝安装。

| 审查状态 | 含义 |
| --- | --- |
| 未审查 | 缺少与完整目录绑定的证据 |
| 审查记录有效 | 指纹、策略、提示词和期限匹配，且该快照的审查结论允许 |
| 内容已变化 | 正文、配套文件、清单或权限与审查快照不同 |
| 无法核验 | 无法取得可完整验证的目录快照 |
| 审查已过期 | 期限、策略或提示词需要更新 |
| 审查未通过 | 审查结论拒绝或要求阻止采用 |

页面显示审查范围、时间和文件指纹。文件变化后，在详情中选择有效模型会话并「重新审查」；复审前后也核验目录是否一致。旧 `auditVerdict` 不能单独构成有效证据；有效记录不保证运行安全，目录中的用途/权限字段也不是执行授权。

文档整合不再给总分，只报告代码围栏、验收章节、注意事项和编号步骤等**实际正文检查结果**，并标记「实际效果未验证」。内置模板与已安装正文分开标识；文件读失败不以模板冒充。整合保留完整段落和代码块；来源带脚本、资源或无法确认完整性时，仅预览，不安装缺少依赖的副本。

模型调用次数随目录大小、分段、最终暂存内容与缓存变化。需求判断使用有限的索引摘要和输入预算，部分名称可能不进入提示；冷索引、过长消息、模型不可用或超时可能跳过推荐。完整核验和受保护执行仍会读盘，不承诺固定调用次数或时延。

## 会话工具保护的范围

- 当前适配 DSH **原生工具模式**：限制工作区文件读取、用户可选的工作区写入及已核验技能资源访问；拒绝敏感路径、shell、终端、外联、任意代码、子代理与未知工具。只读不能写文件，脚本或联网类技能会受限。
- PTC 任意代码通道、缺少必要执行接口或无法核验的工具定义会显示不可用，不会自动放宽后继续安装或启用。
- 首次开启、关闭后重开或 Host 重载时，若旧技能/任意代码历史无法可靠核验，需要新会话。关闭只移除所选会话的运行限制，已加载技能内容可能仍留在对话历史中。
- 保护约束宿主工具调用链，不隔离可信宿主插件自身、其他进程或用户直接运行的程序，也不覆盖模型文本输出、客户端渲染或其他插件自行发起的网络请求。页面安装仍由插件按用户操作写入技能目录。它不是全机沙箱或系统级网络隔离。

启动恢复完成前，持久化保护选择尚未确定，插件会**暂缓全部工具调用**。状态损坏或无法读取时暂停持续并显示原因，需要先恢复状态文件或其 `.bak` 备份；不会把读取失败当作所有会话均未开启保护。宿主信任、文件并发替换等边界见 [安全模型](docs/SECURITY-MODEL.md)。

## 目录、状态与接口

`$DSH_HOME` 默认是 `~/.dsh`。默认安装作用域为全局；工作区作用域需确认 DSH 的技能 provider 能识别项目根（通常需要 `.git`）。

| 作用域 | 位置 |
| --- | --- |
| 全局 | `$DSH_HOME/skills/<name>/SKILL.md` |
| 工作区 | `<workspace>/.dsh/skills/<name>/SKILL.md` |
| 临时 | `$DSH_HOME/skill-detective/temp/<sessionId>/<name>/SKILL.md` |
| 插件自带 | 所属插件提供的目录或内联注册，仅查看 |

禁用使用 `SKILL.md` 的 `disable-model-invocation` 标记；临时注册还绑定会话生命周期。卸载 bundle 后，已安装技能目录仍会保留，需要另行管理。

| 数据文件 | 内容 |
| --- | --- |
| `$DSH_HOME/skill-detective.json` | 实例安装元数据、推荐开关、忽略规则和删除记录 |
| `$DSH_HOME/skill-detective/index.json` | **v3** 实例索引、工作区/会话、目录快照与审查证据 |
| `$DSH_HOME/skill-detective/audit-cache.json` | 与内容、策略和提示词绑定的审查缓存 |
| `$DSH_HOME/skill-detective/runtime-protection.json` | 用户明确选择的会话保护模式与固定工作区 |

同源 Web 接口统一位于 `/api/dsh-skill-detective`：

| 接口 | 用途 |
| --- | --- |
| `GET /state?sessionId=...` | 实例列表、审查状态、可选会话及所选会话保护状态 |
| `POST /scan` | 手动重扫 |
| `POST /review` | 复审确切实例；传 `instanceId`/`path`、`workspace`、显式 `sessionId` |
| `POST /protection` | Web 用户设置保护；传 `sessionId`、布尔 `enabled`、`read-only` 或 `workspace-write` 模式 |

安装、启停、删除和作用域接口同样按实例定位；名称有歧义时不猜目标。状态写入采用原子替换并保留备份；损坏文件保留并报告错误。

## 验证与维护

运行 `npm test`。2026-11-15 本机 Windows 的 Node 22.23.5 / 24.19.0 分别运行 **184 项：179 通过、0 失败、5 项因平台条件跳过**。CI 配置覆盖 Windows / Ubuntu 与 Node 22 / 24，配置存在不等于所有平台已在本机验证。

本机 DSH 0.2.1-rc.5 的真实宿主探针验证了内置 `read` 读取测试文件、内置 `write` 在只读保护下被拒绝。Windows 的 bash 拒绝检查使用没有 shell 实现的无害 marker，其 body 未执行；没有运行真实恶意技能，也没有测量模型恶意样本检出率。测试通过率不能解释为技能实际效果或绝对安全性。
